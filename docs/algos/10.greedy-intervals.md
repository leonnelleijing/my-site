# Greedy & Intervals

A **greedy** algorithm makes the locally best choice at each step and never goes back. It is fast and simple, but only correct when you can argue that the greedy choice is always part of some optimal solution (usually with an **exchange argument**: "any optimal solution can be changed to include my choice without getting worse").

| Greedy works | Greedy fails |
|---|---|
| activity selection (earliest end first) | coin change with coins `[1, 3, 4]` → use [DP](./9.dynamic-programming.md) |
| jump game (track furthest reach) | 0/1 knapsack → DP |
| Huffman coding, Dijkstra, Kruskal | longest path in a general graph |

**Tip:** try to break your greedy with a small counter-example before coding it.

# Intervals

Most interval problems start by **sorting**: by start time to merge, by end time to schedule as many as possible.

```text
[1,3]  ■■■
[2,6]   ■■■■■
[8,10]         ■■■
[15,18]               ■■■■
merged: [1,6] [8,10] [15,18]
```

Two intervals `[a, b]` and `[c, d]` overlap when `a <= d and c <= b`.

# Practice

## 1. Merge Intervals — Medium

```text
Input:  [[1,3], [2,6], [8,10], [15,18]]
Output: [[1,6], [8,10], [15,18]]
```

<details>
<summary>Hint</summary>

Sort by start. If an interval starts before (or when) the last merged one ends, extend the last one's end; otherwise start a new one.

</details>

<details>
<summary>Implementation — O(n log n)</summary>

```python
def merge(intervals):
    intervals.sort(key=lambda x: x[0])
    out = []
    for start, end in intervals:
        if out and start <= out[-1][1]:
            out[-1][1] = max(out[-1][1], end)
        else:
            out.append([start, end])
    return out

assert merge([[1, 3], [2, 6], [8, 10], [15, 18]]) == [[1, 6], [8, 10], [15, 18]]
assert merge([[1, 4], [4, 5]]) == [[1, 5]]
assert merge([[1, 4], [2, 3]]) == [[1, 4]]
```

</details>

## 2. Insert Interval — Medium

Insert a new interval into a sorted, non-overlapping list and merge if needed.

```text
Input:  intervals = [[1,2], [3,5], [6,7], [8,10], [12,16]], new = [4,8]
Output: [[1,2], [3,10], [12,16]]
```

<details>
<summary>Hint</summary>

Three phases in one pass: copy intervals ending before `new` starts; merge all that overlap `new` into it; copy the rest.

</details>

<details>
<summary>Implementation — O(n)</summary>

```python
def insert(intervals, new):
    out, i, n = [], 0, len(intervals)
    start, end = new
    while i < n and intervals[i][1] < start:
        out.append(intervals[i]); i += 1
    while i < n and intervals[i][0] <= end:
        start = min(start, intervals[i][0])
        end = max(end, intervals[i][1])
        i += 1
    out.append([start, end])
    out.extend(intervals[i:])
    return out

assert insert([[1, 2], [3, 5], [6, 7], [8, 10], [12, 16]], [4, 8]) == [[1, 2], [3, 10], [12, 16]]
assert insert([], [5, 7]) == [[5, 7]]
```

</details>

## 3. Non-overlapping Intervals — Medium

Minimum number of intervals to remove so the rest don't overlap.

```text
Input:  [[1,2], [2,3], [3,4], [1,3]]
Output: 1           (remove [1,3])
```

<details>
<summary>Hint</summary>

Activity selection: sort by **end** and keep an interval whenever it starts after the last kept one ends. Ending early leaves the most room for the rest. Removed = total − kept.

</details>

<details>
<summary>Implementation — O(n log n)</summary>

```python
def erase_overlap_intervals(intervals):
    intervals.sort(key=lambda x: x[1])
    kept, last_end = 0, float("-inf")
    for start, end in intervals:
        if start >= last_end:
            kept += 1
            last_end = end
    return len(intervals) - kept

assert erase_overlap_intervals([[1, 2], [2, 3], [3, 4], [1, 3]]) == 1
assert erase_overlap_intervals([[1, 2], [1, 2], [1, 2]]) == 2
assert erase_overlap_intervals([[1, 2], [2, 3]]) == 0
```

</details>

## 4. Meeting Rooms II — Medium

Minimum number of rooms so all meetings can happen.

```text
Input:  [[0,30], [5,10], [15,20]]
Output: 2
```

<details>
<summary>Hint</summary>

Sort by start; keep a min-heap of end times of meetings in progress. If the earliest-ending room is free by the time the next meeting starts, reuse it (pop). The heap size at the end is the answer.

Alternative: sweep line over sorted starts and sorted ends.

</details>

<details>
<summary>Implementation — O(n log n)</summary>

```python
import heapq

def min_meeting_rooms(intervals):
    intervals.sort(key=lambda x: x[0])
    ends = []                                # end times of rooms in use
    for start, end in intervals:
        if ends and ends[0] <= start:
            heapq.heappop(ends)              # that room is free again
        heapq.heappush(ends, end)
    return len(ends)

assert min_meeting_rooms([[0, 30], [5, 10], [15, 20]]) == 2
assert min_meeting_rooms([[7, 10], [2, 4]]) == 1
assert min_meeting_rooms([[1, 5], [2, 6], [3, 7]]) == 3
```

</details>

## 5. Jump Game — Medium

`nums[i]` is the maximum jump length from index `i`. Can you reach the last index?

```text
[2, 3, 1, 1, 4] → True
[3, 2, 1, 0, 4] → False    (always stuck at index 3)
```

<details>
<summary>Hint</summary>

Track the **furthest index reachable** so far. If you ever stand on an index beyond it, you're stuck.

</details>

<details>
<summary>Implementation — O(n)</summary>

```python
def can_jump(nums):
    reach = 0
    for i, jump in enumerate(nums):
        if i > reach:
            return False
        reach = max(reach, i + jump)
    return True

assert can_jump([2, 3, 1, 1, 4])
assert not can_jump([3, 2, 1, 0, 4])
assert can_jump([0])
```

</details>

## 6. Jump Game II — Medium

Same input; minimum number of jumps to reach the last index (always reachable).

```text
[2, 3, 1, 1, 4] → 2     (0 → 1 → 4)
```

<details>
<summary>Hint</summary>

BFS by levels without a queue: all indices reachable with `k` jumps form a window `[l, r]`. The next window ends at the furthest reach from inside the current one.

</details>

<details>
<summary>Implementation — O(n)</summary>

```python
def jump(nums):
    jumps, current_end, furthest = 0, 0, 0
    for i in range(len(nums) - 1):
        furthest = max(furthest, i + nums[i])
        if i == current_end:               # must jump to go further
            jumps += 1
            current_end = furthest
    return jumps

assert jump([2, 3, 1, 1, 4]) == 2
assert jump([2, 3, 0, 1, 4]) == 2
assert jump([0]) == 0
```

</details>

## 7. Gas Station — Medium

Circular route; `gas[i]` fuel at station `i`, `cost[i]` to drive to the next. Return the start index to complete the loop, or `-1`.

```text
gas = [1,2,3,4,5], cost = [3,4,5,1,2] → 3
```

<details>
<summary>Hint</summary>

If total gas < total cost, impossible. Otherwise drive from 0 keeping the tank; whenever it goes negative at station `i`, no start between the current start and `i` works, so restart at `i + 1`.

</details>

<details>
<summary>Implementation — O(n)</summary>

```python
def can_complete_circuit(gas, cost):
    if sum(gas) < sum(cost):
        return -1
    start, tank = 0, 0
    for i in range(len(gas)):
        tank += gas[i] - cost[i]
        if tank < 0:
            start, tank = i + 1, 0
    return start

assert can_complete_circuit([1, 2, 3, 4, 5], [3, 4, 5, 1, 2]) == 3
assert can_complete_circuit([2, 3, 4], [3, 4, 3]) == -1
```

</details>

## 8. Maximum Subarray (Kadane) — Medium

Largest sum of a contiguous subarray.

```text
[-2, 1, -3, 4, -1, 2, 1, -5, 4] → 6     ([4, -1, 2, 1])
```

<details>
<summary>Hint</summary>

At each element, either extend the current subarray or start fresh, whichever is bigger: `current = max(x, current + x)`. A negative running sum never helps what comes next.

</details>

<details>
<summary>Implementation — O(n)</summary>

```python
def max_sub_array(nums):
    best = current = nums[0]
    for x in nums[1:]:
        current = max(x, current + x)
        best = max(best, current)
    return best

assert max_sub_array([-2, 1, -3, 4, -1, 2, 1, -5, 4]) == 6
assert max_sub_array([-3, -1, -2]) == -1
assert max_sub_array([5, 4, -1, 7, 8]) == 23
```

</details>

# Self-check

<details>
<summary>Why sort by end time (not start time) to keep the most non-overlapping intervals?</summary>

The interval that ends first leaves the most time for all the others. Exchange argument: in any optimal solution, replace its first interval with the one that ends earliest; it still doesn't overlap the rest, and the count is unchanged. Sorting by start fails on `[[1, 100], [2, 3], [4, 5]]`.

</details>

<details>
<summary>How do you prove a greedy algorithm is correct in an interview?</summary>

Give the exchange argument in one or two sentences, or show the greedy choice "stays ahead" of any other solution at every step. If you can't, test small counter-examples; if one breaks it, switch to DP.

</details>
