# ML Basics

The math that the CS50 "Learning" and "Neural Networks" lectures build on (the same material as Andrew Ng's *Machine Learning Specialization*, course 1).

**Notation**

| Symbol | Meaning |
|---|---|
| $m$ | number of training examples |
| $n$ | number of features |
| $x^{(i)}$, $y^{(i)}$ | features and true label of example $i$ |
| $x_j$ | the $j$-th feature |
| $\mathbf{w}$, $b$ | weights and bias, the parameters we learn |
| $\hat{y} = f_{\mathbf{w},b}(x)$ | the model's prediction |

# Linear regression

Predict a **continuous** number (house price, temperature) from input features.

$$
f_{w,b}(x) = wx + b \qquad\qquad f_{\mathbf{w},b}(\mathbf{x}) = \mathbf{w} \cdot \mathbf{x} + b = w_1x_1 + w_2x_2 + \dots + w_nx_n + b
$$

The model is a straight line (one feature) or a hyperplane (many features). **Learning = finding the `w, b` that make the line fit the data best.**

**Example**: house size (1000 sq ft) → price (1000s of dollars).

| size $x$ | price $y$ |
|---|---|
| 1.0 | 300 |
| 2.0 | 500 |
| 3.0 | 700 |

Here $w = 200$, $b = 100$ fits perfectly: $f(2.5) = 200(2.5) + 100 = 600$.

## Cost function

The cost function measures **how wrong** the model is over the whole training set. Linear regression uses the **squared error** cost:

$$
J(w, b) = \frac{1}{2m} \sum_{i=1}^{m} \left( f_{w,b}(x^{(i)}) - y^{(i)} \right)^2
$$

- Squaring makes every error positive and punishes large errors more.
- The $\tfrac{1}{2}$ is only there so the derivative comes out cleaner.
- Goal: $\min_{w,b} J(w, b)$.
- For linear regression $J$ is **convex** (a bowl): there is only one minimum, the global one.

**Worked example** with the data above and a bad guess $w = 150, b = 100$:

| $x$ | $y$ | $\hat{y} = 150x + 100$ | error | error² |
|---|---|---|---|---|
| 1 | 300 | 250 | −50 | 2500 |
| 2 | 500 | 400 | −100 | 10000 |
| 3 | 700 | 550 | −150 | 22500 |

$$
J(150, 100) = \frac{1}{2 \cdot 3}(2500 + 10000 + 22500) = \frac{35000}{6} \approx 5833
$$

With $w = 200, b = 100$ every error is 0, so $J = 0$.

```python
import numpy as np

def compute_cost(x, y, w, b):
    m = len(x)
    return ((w * x + b - y) ** 2).sum() / (2 * m)

x = np.array([1.0, 2.0, 3.0]); y = np.array([300.0, 500.0, 700.0])
print(compute_cost(x, y, 150, 100))   # 5833.33
print(compute_cost(x, y, 200, 100))   # 0.0
```

## gradient descent

An iterative algorithm to find the minimum of $J$: start somewhere and take small steps **downhill**, in the direction of the negative gradient.

$$
\text{repeat until convergence:} \qquad
w \leftarrow w - \alpha \frac{\partial J}{\partial w} \qquad
b \leftarrow b - \alpha \frac{\partial J}{\partial b}
$$

For linear regression the derivatives are:

$$
\frac{\partial J}{\partial w} = \frac{1}{m} \sum_{i=1}^{m} \left( f_{w,b}(x^{(i)}) - y^{(i)} \right) x^{(i)}
\qquad
\frac{\partial J}{\partial b} = \frac{1}{m} \sum_{i=1}^{m} \left( f_{w,b}(x^{(i)}) - y^{(i)} \right)
$$

<details>
<summary>Derivation (chain rule)</summary>

$$
\frac{\partial}{\partial w} \frac{1}{2m}\sum (wx^{(i)} + b - y^{(i)})^2
= \frac{1}{2m}\sum 2(wx^{(i)} + b - y^{(i)}) \cdot x^{(i)}
= \frac{1}{m}\sum (f(x^{(i)}) - y^{(i)})\,x^{(i)}
$$

The 2 from the power cancels the ½, which is why we put the ½ there.
</details>

![Gradient descent with a good and a too-large learning rate](/img/cs50/gradient-descent.svg)

- $\alpha$ is the **learning rate**:
  - too small → many tiny steps, very slow;
  - too large → overshoots the minimum, may **diverge** (cost goes up).
- Update $w$ and $b$ **simultaneously**: compute both gradients first, then assign both.
- Near the minimum the gradient gets smaller, so steps shrink automatically even with a fixed $\alpha$.
- **Batch** GD uses all $m$ examples per step; **stochastic** GD uses 1; **mini-batch** uses a small group, the usual choice in deep learning.
- Check convergence with a **learning curve**: plot $J$ against iterations. It should go down every iteration.

**Worked example — one step** (data above, start $w = 0, b = 0$, $\alpha = 0.1$):

$$
\begin{aligned}
\text{errors} &= (0-300,\ 0-500,\ 0-700) = (-300, -500, -700) \\
\tfrac{\partial J}{\partial w} &= \tfrac{1}{3}\big((-300)(1) + (-500)(2) + (-700)(3)\big) = \tfrac{-3400}{3} \approx -1133.3 \\
\tfrac{\partial J}{\partial b} &= \tfrac{1}{3}(-300 - 500 - 700) = -500 \\
w &\leftarrow 0 - 0.1(-1133.3) = 113.3 \qquad b \leftarrow 0 - 0.1(-500) = 50
\end{aligned}
$$

```python
def gradient_descent(X, y, alpha=0.01, iters=1000):
    """X: (m, n) features, y: (m,) targets. Returns w, b and cost history."""
    m, n = X.shape
    w, b = np.zeros(n), 0.0
    history = []
    for _ in range(iters):
        err = X @ w + b - y               # (m,) prediction errors
        dj_dw = X.T @ err / m             # (n,)
        dj_db = err.mean()
        w, b = w - alpha * dj_dw, b - alpha * dj_db   # simultaneous update
        history.append((err ** 2).mean() / 2)
    return w, b, history

X = x.reshape(-1, 1)
w, b, hist = gradient_descent(X, y, alpha=0.1, iters=5000)
print(w.round(2), round(b, 2))    # [200.] 100.0
```

## Multiple features & vectorization

$$
f_{\mathbf{w},b}(\mathbf{x}) = \mathbf{w} \cdot \mathbf{x} + b
\qquad
w_j \leftarrow w_j - \alpha \frac{1}{m}\sum_{i=1}^{m}\left(f(\mathbf{x}^{(i)}) - y^{(i)}\right)x_j^{(i)}
$$

**Vectorization**: `np.dot(w, x)` runs in parallel hardware and is much faster than a Python `for` loop over features.

## Feature scaling

If features have very different ranges (size 300–2000 sq ft vs. bedrooms 0–5), the cost contours become long, thin ellipses and gradient descent zig-zags slowly. Rescale the features to similar ranges:

| Method | Formula | Result |
|---|---|---|
| Max scaling | $x / \max(x)$ | 0 … 1 |
| Mean normalization | $\dfrac{x - \mu}{\max - \min}$ | about −1 … 1 |
| **Z-score normalization** | $\dfrac{x - \mu}{\sigma}$ | mean 0, std 1 |

**Example**: sizes `[1000, 1500, 2000]` → $\mu = 1500$, $\sigma \approx 408$ → z-scores `[-1.22, 0, 1.22]`.

```python
def zscore(X):
    mu, sigma = X.mean(axis=0), X.std(axis=0)
    return (X - mu) / sigma, mu, sigma

X_norm, mu, sigma = zscore(X_train)
X_test_norm = (X_test - mu) / sigma     # reuse the TRAINING mu and sigma!
```

Rule of thumb: aim for roughly −1 … 1 per feature. Always apply the **same** $\mu, \sigma$ (computed on the training set) to new data.

**Feature engineering**: create new features from existing ones, e.g. `area = width × depth`. **Polynomial regression**: add $x^2, x^3$ as features to fit curves (then scaling is essential, since $x^3$ gets huge).

# Classification

Predict a **discrete category**: spam / not spam, tumor malignant / benign. Linear regression is a bad fit here because its output isn't limited to 0…1, and a single far-away example shifts the threshold.

## Logistic regression

Pass the linear output through the **sigmoid** function so the result lies between 0 and 1, and read it as a probability.

$$
z = \mathbf{w}\cdot\mathbf{x} + b
\qquad
g(z) = \frac{1}{1 + e^{-z}}
\qquad
f_{\mathbf{w},b}(\mathbf{x}) = g(\mathbf{w}\cdot\mathbf{x} + b) = P(y = 1 \mid \mathbf{x}; \mathbf{w}, b)
$$

![Sigmoid function](/img/cs50/sigmoid.svg)

| $z$ | −∞ | −2 | 0 | 2 | +∞ |
|---|---|---|---|---|---|
| $g(z)$ | 0 | 0.12 | 0.5 | 0.88 | 1 |

**Decision boundary**: predict 1 when $f \ge 0.5$, i.e. when $z = \mathbf{w}\cdot\mathbf{x} + b \ge 0$.

**Example**: $w_1 = 1, w_2 = 1, b = -3$ → boundary $x_1 + x_2 = 3$ (a line). With polynomial features, e.g. $z = x_1^2 + x_2^2 - 1$, the boundary is the **circle** $x_1^2 + x_2^2 = 1$.

### Loss: binary cross-entropy

Squared error + sigmoid gives a **non-convex** cost with many local minima. Use the **log loss** instead:

$$
L(f, y) = \begin{cases} -\log(f) & \text{if } y = 1 \\ -\log(1 - f) & \text{if } y = 0 \end{cases}
\quad = \; -y\log(f) - (1-y)\log(1-f)
$$

- $y = 1$ and $f \to 1$: loss → 0. $y = 1$ and $f \to 0$: loss → ∞ (confident **and** wrong is punished heavily).

| true $y$ | prediction $f$ | loss |
|---|---|---|
| 1 | 0.9 | $-\ln 0.9 = 0.105$ |
| 1 | 0.1 | $-\ln 0.1 = 2.303$ |
| 0 | 0.2 | $-\ln 0.8 = 0.223$ |

$$
J(\mathbf{w}, b) = -\frac{1}{m}\sum_{i=1}^{m}\Big[y^{(i)}\log f(\mathbf{x}^{(i)}) + (1 - y^{(i)})\log\big(1 - f(\mathbf{x}^{(i)})\big)\Big]
$$

The gradient descent update has **exactly the same form** as linear regression, only $f$ is different:

$$
w_j \leftarrow w_j - \alpha\frac{1}{m}\sum_{i=1}^{m}\big(f(\mathbf{x}^{(i)}) - y^{(i)}\big)x_j^{(i)}
$$

```python
def sigmoid(z):
    return 1 / (1 + np.exp(-z))

def logistic_cost(X, y, w, b):
    f = sigmoid(X @ w + b)
    return -(y * np.log(f) + (1 - y) * np.log(1 - f)).mean()

def train_logistic(X, y, alpha=0.1, iters=5000):
    w, b = np.zeros(X.shape[1]), 0.0
    for _ in range(iters):
        err = sigmoid(X @ w + b) - y
        w -= alpha * X.T @ err / len(y)
        b -= alpha * err.mean()
    return w, b

X = np.array([[0.5, 1.5], [1, 1], [1.5, 0.5], [3, 0.5], [2, 2], [1, 2.5]])
y = np.array([0, 0, 0, 1, 1, 1])
w, b = train_logistic(X, y)
print(sigmoid(np.array([2.5, 1.5]) @ w + b))   # probability of class 1 (close to 1)
```

With scikit-learn:

```python
from sklearn.linear_model import LogisticRegression
model = LogisticRegression().fit(X, y)
print(model.predict([[2.5, 1.5]]), model.predict_proba([[2.5, 1.5]]))
```

## Overfitting & regularization

![Underfit vs good fit vs overfit](/img/cs50/fitting.svg)

| | Underfit (high bias) | Just right | Overfit (high variance) |
|---|---|---|---|
| Training error | high | low | very low |
| Test error | high | low | **high** |

Ways to fix overfitting:

1. Collect **more** training data.
2. Use **fewer** features (feature selection).
3. **Regularization**: keep all features but shrink the weights.

$$
J(\mathbf{w}, b) = \underbrace{\frac{1}{2m}\sum_{i=1}^{m}\big(f(\mathbf{x}^{(i)}) - y^{(i)}\big)^2}_{\text{fit the data}} + \underbrace{\frac{\lambda}{2m}\sum_{j=1}^{n} w_j^2}_{\text{keep } w_j \text{ small}}
$$

The update becomes:

$$
w_j \leftarrow w_j\Big(1 - \alpha\frac{\lambda}{m}\Big) - \alpha\frac{1}{m}\sum_{i=1}^{m}\big(f(\mathbf{x}^{(i)}) - y^{(i)}\big)x_j^{(i)}
$$

So each step first shrinks $w_j$ a little ("weight decay"), then does the usual update. $\lambda$ large → underfit; $\lambda = 0$ → no regularization. By convention $b$ isn't regularized.

# Self-check

<details>
<summary>1. Why do we square the error in the cost function?</summary>

So positive and negative errors don't cancel, large errors are punished more, and the cost is smooth and convex, which makes it easy to differentiate.
</details>

<details>
<summary>2. What happens if the learning rate is too large? Too small?</summary>

Too large: overshoots, oscillates, and may diverge (cost increases). Too small: converges very slowly.
</details>

<details>
<summary>3. Compute one gradient step: data (x=1,y=2), start w=0, b=0, α=0.5.</summary>

error = 0 − 2 = −2 → ∂J/∂w = −2, ∂J/∂b = −2 → w = 1, b = 1.
</details>

<details>
<summary>4. Why can't we use squared error for logistic regression?</summary>

With the sigmoid inside, the squared-error cost is non-convex (it has many local minima), so gradient descent may get stuck. Log loss is convex.
</details>

<details>
<summary>5. Logistic regression outputs 0.8. What does that mean?</summary>

An estimated **80% probability that y = 1** for this input. We'd predict class 1 since 0.8 ≥ 0.5.
</details>

<details>
<summary>6. What does λ do in regularization?</summary>

It controls the trade-off between fitting the training data and keeping the weights small. Bigger λ gives a simpler model.
</details>
